# MinionX Update — Version 1.0.3

## Release Overview
**MinionX v1.0.3** is a stability, compatibility, and security release for Paper/Spigot 1.20.4+. This update delivers native island protection integration for **SuperiorSkyblock2**, full compatibility updates across 16 supported soft dependencies, multi-item tier upgrade requirements with an in-game checklist, composite multi-behavior upgrades, an in-game Upgrade Creator Studio, centralized custom skull/head rendering, PersistentDataContainer data value tracking for compressed items, and full-inventory drop protection.

---

## Key Highlights & Technical Changes

### 1. SuperiorSkyblock2 & Island Region Protection (`ProtectionHookManager`)
- **Island Boundary Enforcement**: Minions can now only be placed inside the placing player's own island boundaries (`ProtectionHookManager.canPlaceMinion`). Placement on foreign islands or wilderness/void chunks is prevented.
- **Team Access & Co-op Support**: Configured under `security.access-mode: TEAM_ACCESS` and `FULL_COOP`. Queries `Island.isMember` and `Island.isCoop` to allow team members to access minion menus and deposit fuel while restricting minion pickup to island owners (unless `security.allow-team-pickup: true` is set).
- **9-Point Perimeter Verification**: Evaluates the minion's entire working perimeter (5x5, or 7x7 with Minion Expander) against WorldGuard, SuperiorSkyblock2, BentoBox, Towny, Lands, and GriefPrevention claims before allowing placement.
- **Clean Reloads**: Cached reflection handles are cleared on server reload or disable to prevent ClassLoader leaks.

### 2. Multi-Item Tier Upgrades & Interactive Checklist
- **Configurable Multi-Item Requirements**: Configure multiple distinct item requirements per tier upgrade in `minions.yml` and `tiers.yml` (e.g. Cobblestone + Coal).
- **Dynamic In-Game Checklist**: Minion menus display a live upgrade checklist showing item requirements and real-time inventory counts with status indicators (`§a✔ Have: X/Y` / `§c✘ Have: X/Y`).
- **Data Value Protection for Compressed Items**:
  - Compressed/Enchanted items generated by MinionX Super Compactor are tagged with a canonical PersistentDataContainer data value (`minionx:compressed = "<recipe_id>"`).
  - Low-tier vanilla requirements strictly reject compressed items, preventing expensive compressed resources (e.g. Enchanted Diamonds) from being accidentally consumed for basic tier upgrades.
  - High-tier requirements match candidate items by PDC data value, recipe identifier, and custom model data.

### 3. In-Game Upgrade Creator Studio & Multi-Item Spreading
- **Modular Creator Dashboard**: Open `/minion create upgrade <id>` to access a 54-slot creator studio supporting composite multi-behavior configuration: Auto-Smelter, Compactor / Super Compactor mode cycle, Speed Buff (+/- 5%), Area Expansion (+/- 1 block), and Auto-Seller (+/- 5%).
- **Multi-Item Spreading Shelf (Slots 20–24)**: Configure up to 5 distinct spreading drops per upgrade. Custom display names, custom model data, and external plugin hook IDs (ItemsAdder, MMOItems, Nexo, Oraxen, EcoItems) are preserved when adjusting quantities (+/- 1) or chances (+/- 5%).
- **Online & Offline Auto-Smelter Parity**: Smeltable conversions (`COBBLESTONE` -> `STONE`, `RAW_*` -> ingots, `*_LOG`/`*_WOOD` -> `CHARCOAL`, `SAND` -> `GLASS`, `CLAY_BALL` -> `BRICK`, `CACTUS` -> `GREEN_DYE`, `POTATO` -> `BAKED_POTATO`) execute identically across both online ticking and offline catchup simulation.

### 4. Unified Skull Engine & Placeholder Fixes
- **Centralized `SkullUtil`**: Normalizes skull textures across armor stands, GUI menus, item stacks, and creator sessions. Supports Base64 texture payloads, direct Mojang URLs (`textures.minecraft.net`), 64-character hex skin hashes, player usernames, and UUIDs.
- **`%tier_roman%` Support**: Corrected `%tier_roman%` placeholder replacement on central minion heads in `MinionGUI`.

### 5. GUI Inventory Overflow Safety
- **Zero-Loss Drop Protection**: Removing or swapping upgrades, fuels, hoppers, or skins when the player inventory is full now drops excess items naturally at the player's feet via `player.getWorld().dropItemNaturally(...)`, eliminating item loss from full inventories.

### 6. External Plugin Ecosystem Hardening
- **Vault Economy**: Supports canonical `OfflinePlayer` signatures with tiered parameter fallbacks.
- **PlaceholderAPI**: Native expansion registering `%minionx_placed%`, `%minionx_limit%`, `%minionx_available%`, `%minionx_bonus%`, and `%minionx_quarantine_status%`.
- **Bedrock / Floodgate**: Compatible with Floodgate 2.0+ `isFloodgatePlayer(UUID)` and standalone `GeyserApi`.
- **MythicMobs**: Dual-compatibility with MythicMobs v5 (`MythicBukkit`) and v4 (`MythicMobs`).
- **Java Compatibility**: Fully compiled and tested on Java 17 and Java 21 LTS runtimes.

## Configuration Guidance: Hologram Visibility (`nametags.mode`)

In `config.yml`, floating minion nametag rendering is governed by `nametags.mode`:
- `ALWAYS` (default): Holograms are always visible up to standard entity tracking distance (~64 blocks).
- `TARGETED`: Holograms delegate proximity culling to client-side view distance rendering (`Display.setViewRange(0.1f)`), rendering only when a player is within ~6.4 blocks. Note that client video settings ("Entity Distance") or server `spigot.yml` `entity-tracking-range` settings dictate ArmorStand visibility independently of TextDisplays.
- `DISABLED`: Disables floating nametag entities completely.

## Upgrade Instructions

1. Stop your Minecraft server.
2. Replace `MinionX.jar` in your `plugins/` directory with `MinionX-1.0.3.jar`.
3. If upgrading from v1.0.2 or earlier:
   - Your existing minion data and configuration files are backward-compatible and will load automatically.
   - A default `storages.yml` template is now bundled for storage chest customization.
4. Start your server.
