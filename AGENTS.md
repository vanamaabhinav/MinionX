# Agent Behavioral Rules & Grounded Output Guidelines

## Grounded Descriptions & Verifiable Claims
1. **Strictly Grounded Content**: All descriptions, changelogs, technical summaries, release notes, and documentation written by the agent MUST be strictly grounded in actual code, verified test results, and explicit configuration options.
2. **No Unprovable or Inflated Claims**:
   - Never use marketing buzzwords, unsubstantiated hype, or subjective superlatives (e.g. "revolutionary", "game-changing", "unrivaled", "100% bug-free", "blazing fast", "ultimate", "state-of-the-art").
   - Never claim absolute zero overhead or perfection unless backed by concrete architecture (e.g. state "delegates to client-side view-distance rendering rather than running server tick loops" instead of "revolutionary zero-overhead engine").
3. **Technical and Objective Tone**:
   - Explicitly state exact configuration keys, class names, file paths, methods, and verified behaviors.
   - Present features clearly, objectively, and accurately so server owners and buyers understand exactly how the system behaves without marketing exaggeration.
